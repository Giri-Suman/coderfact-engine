## 7 tips that actually move the needle

### Tip 1. Use Pydantic to strictly define tool arguments
_Why it matters:_ LLMs are notoriously bad at guessing unstructured inputs, but they respect JSON schemas generated by Pydantic.

```python
from pydantic import BaseModel
class SearchQuery(BaseModel):
    query: str
```

### Tip 2. Bind tools directly using the openai library
_Why it matters:_ Instead of parsing raw text, use the native tool-calling interface to get clean JSON payloads back.

```
client.chat.completions.create(model='gpt-4o', messages=msgs, tools=tools)
```

### Tip 3. Enforce a hard max_iterations loop guard
_Why it matters:_ Without a loop counter, a confused agent will call the same failing tool forever, draining your wallet.

```
for _ in range(max_loops):
    if action == 'stop': break
```

### Tip 4. Use python-dotenv for zero-config environment management
_Why it matters:_ Hardcoding API keys in your agent script is a disaster waiting to happen when you push to GitHub.

```python
from dotenv import load_dotenv
import os
load_dotenv()
```

### Tip 5. Debug agent state transitions with the icecream library
_Why it matters:_ Standard print statements get buried in LLM logs; icecream makes it obvious what variables changed and where.

```python
from icecream import ic
ic(agent_response.choices[0].message.tool_calls)
```

### Tip 6. Catch tool execution errors and feed them back to the LLM
_Why it matters:_ If a tool crashes, sending the traceback back to the agent allows it to self-correct and try a different approach.

```
except Exception as e:
    messages.append({'role': 'tool', 'content': str(e)})
```

### Tip 7. Use rich to format terminal outputs of the agent's thought process
_Why it matters:_ Separating thoughts, tool calls, and tool results visually saves you from squinting at raw JSON walls.

```python
from rich import print
print('[bold green]Agent Thought:[/bold green]', thought)
```

## Step-by-step procedure

### 1. Step 1: Install dependencies and set up the environment
Create a virtual environment and install the required packages. We will use the official OpenAI client and Pydantic for defining our tools.

```python
pip install openai pydantic python-dotenv
```

### 2. Step 2: Define your python tool functions
Write the actual Python functions your agent will execute. Add type hints and clean docstrings—the LLM reads these to understand when to use them.

```python
def calculate_directory_size(path: str) -> int:
    """Returns total size of a directory in bytes."""
    return sum(f.stat().st_size for f in Path(path).glob('**/*') if f.is_file())
```

### 3. Step 3: Format tools for the LLM
Convert your Python functions into helper schemas that the OpenAI API expects using Pydantic or direct dictionary mapping.

```
tools = [{
    'type': 'function',
    'function': {
        'name': 'calculate_directory_size',
        'description': 'Get directory size',
        'parameters': {'type': 'object', 'properties': {'path': {'type': 'string'}}}
    }
}]
```

### 4. Step 4: Build the execution loop with a safety guard
Write the loop that sends messages to the model, checks if it requested a tool call, runs the local function, and feeds the output back.

```
messages = [{'role': 'user', 'content': 'Check the size of ./logs'}]
for _ in range(5):
    response = client.chat.completions.create(model='gpt-4o', messages=messages, tools=tools)
    # handle tool calls here
```

### 5. Step 5: Run and verify the agent
Execute your script. The agent should analyze your prompt, decide to call the directory size function, run it, and print the correct final answer.

```
python agent.py
```

## The mistake almost everyone makes

> ⚠️  Forgetting to handle the case where the LLM decides *not* to call any tools. If you assume there is always a tool call in the response, your script will throw an AttributeError. Always check if 'tool_calls' is present in the message object before trying to loop through them.
