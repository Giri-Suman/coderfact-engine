# Beliefs

Positions I actually hold. Each one should be something a competent engineer
could argue with — that is what makes a piece worth reading instead of worth
skimming.

These are drafted from how the work has actually gone. Edit them until they
sound like you arguing at 1am, not like a summary. Delete any you would not
defend in a comment thread.

- Most "AI agent" tutorials are architecture diagrams with no working orchestration. They rank because the diagram is screenshot-friendly, and they help nobody, because the hard part was never the boxes.
- A benchmark published without the machine spec is a vibe with a number attached.
- The bug that costs you a day is almost never the one that raises. It is the one that returns null, or an empty list, or a green pipeline over an empty repo.
- If a tool needs a README longer than its source, the interface is wrong and the README is an apology.
- LLM output does not need a sterner prompt, it needs better inputs. Every time I have tightened an instruction instead of supplying real material, the model has found a new way to be plausible.
- Automating the writing is the easy half. Automating the checking is where the actual engineering is, and it is the half everyone skips because it produces nothing to post.
- "It works on my machine" is fine. "I never opened the published version" is not — and I did that for months.
- Free-tier infrastructure is a feature, not a constraint. The moment a pipeline needs a credit card it needs a decision, and a decision is a thing that stops running at 8am.
- Shipping a draft is not shipping. Nothing in my pipeline publishes itself, and the day I remove that gate is the day it publishes something with a fabricated number in the title.
